# Audit v2.6.2 — audit complet du code et stabilisation

Audit réalisé le 13/10/2026 sur `main` @ `87ac3fe` (v2.6.1), en lecture seule. Le `main` distant a
reçu depuis `b049919` (README, voir D-01). Méthode : mesures lancées par le coordinateur, puis six
audits indépendants, un par axe (architecture, TypeScript et tests, sécurité, garde-fou cyber et
fidélité, performances et interface, documentation et dépôt). Chaque constat est étayé par
fichier:ligne ; un constat non reproduit est marqué « à confirmer ».

## 1. Synthèse

**Note globale : 7,5 / 10.**

- Socle solide : moteur pur respecté (0 import interdit, 0 `Math.random`/`Date.now`), 803 tests verts
  et stables sur 5 passages, 82 E2E verts, 91,9 % des lignes du moteur couvertes, typage strict
  (1 seul `any`, justifié), CSP de production stricte, IPC entièrement validé, garde-fou cyber
  conforme (aucun code offensif réel).
- Ce qui retire des points : la CI est rouge sur `main` (Prettier, D-01) ; un fichier glissé hors
  du canvas remplace la page et expose l'API du preload (S-01, 🔴) ; la chaîne de release donne un
  jeton d'écriture aux scripts npm et l'installeur n'est pas signé (S-03, S-04) ; un calcul en
  O(n²) fige le canvas à chaque modification réseau (P-01) ; les dialogues laissent passer les
  raccourcis du canvas (U-01) ; les dépendances entre rôles ne sont pas déclarées (A-01).
- Bilan : **1 🔴, 21 🟠, 57 🟡, 12 ⚪.** Aucun constat ne remet en cause l'architecture ; la plupart
  des corrections sont de taille S.

## 4. Ce qui va bien (à conserver tel quel)

- **Moteur pur** : seuls `immer` et `zod` importés ; aucun React, Electron, `node:*`, DOM, `Math.random`
  ni `Date.now` ; PRNG local seedé pour Red/Blue ; `tsconfig.engine.json` sans `DOM`.
- **Façade unique** `@engine/index` (aucun import profond depuis l'interface) ; registres cohérents
  (rôles, fonctionnalités IOS, scénarios cyber, outils bash) ; commandes nommées et `dispatch`.
- **Tests** : 803 tests stables sur 5 passages, 82 E2E sans instabilité, 91,9 % de lignes couvertes ;
  un fichier de référence par version `.slab` (v1 → v14) et un test par migration.
- **Typage** : `strict` + `noUncheckedIndexedAccess`, 1 seul `any` justifié, 0 `@ts-ignore`, toutes les
  assertions `!` justifiées.
- **Sécurité Electron** : `contextIsolation`, `sandbox`, `nodeIntegration: false` sur les deux fenêtres ;
  `setWindowOpenHandler`, webviews et permissions refusés globalement ; CSP de production sans
  `unsafe-inline` ni `unsafe-eval` ; preload minimal ; 28 canaux IPC validés, aucun accès disque
  générique ; `.slab` borné en taille, sans pollution de prototype (vérifié), migrations défensives.
- **Liste blanche d'URL** robuste aux contournements classiques (userinfo, port, sous-domaine,
  `javascript:`, `file:`, `data:`, `..` encodé).
- **Garde-fou cyber** conforme : aucun code offensif réel, empreintes et mots de passe factices,
  effets abstraits sur l'état ; documenté dans `CLAUDE.md` et `docs/fidelite.md` (C1 → C16).
- **Fidélité** : messages Windows FR très fidèles ; marqueur `^`, `% Incomplete command.`,
  `% Ambiguous command:` exacts sous IOS ; `docs/fidelite.md` couvre v2.5, v2.6 et v2.6.1.
- **Performances du glisser** : 0,14 ms par mouvement à 100 équipements, 0 rendu parasite ; historiques
  bornés ; écouteurs, IPC et minuteurs nettoyés (à deux exceptions près).
- **i18n** : 688 clés FR/EN cohérentes ; écrans v2.5 et v2.6 traduits et compatibles avec les thèmes.
- **Dépôt** : versions concordantes, chaîne de release fonctionnelle, aucun secret ni artefact versionné.

## 5. Points à traiter avant la v2.7

La refonte de l'horloge rendra ces points plus coûteux à corriger ensuite :

1. **P-01** : chaque avancée d'horloge qui change le réseau (bail expiré, APIPA) recalculera le canvas ;
   en O(n²), un tick coûterait déjà 24 ms à 100 équipements.
2. **A-02** : les tâches de fond hors `dispatch` et hors journal ; avec une horloge qui avance,
   l'annulation deviendrait incohérente. Écrire d'abord le test « annuler puis tâches de fond ».
3. **A-10** : centraliser le temps (`core/clock.ts`) : époque unique, constantes, formateurs.
4. **A-05** : casser les cycles `sim/forward` ↔ rôles et `net/` ↔ `ios/registry` avant d'ajouter un
   ordonnanceur (une tâche évaluée au chargement révélerait l'ordre d'initialisation).
5. **Tests de caractérisation du temps** (T-01, T-13) : figer le comportement actuel des baux DHCP, du
   verrouillage, des heures ouvrées et de la détection cyber (`windowMs`) avant de le changer ;
   helper unique `advanceClock` au lieu des 4 fichiers de tests qui modifient `clock` directement.
6. **A-07** : sortir la logique Red/Blue (et son minuteur réel) du store React.
7. **A-01** : déclarer les dépendances réelles entre rôles avant que la v2.7 n'ajoute des tâches
   de fond qui s'appellent entre rôles.

Constats propres à la conception de la v2.7 (notés, pas à corriger en v2.6.2) : l'horloge n'avance
que de 1 s par évènement journalisé (`core/eventlog.ts:13,44`) ; les échéances des baux DHCP
(`expiresAt`) et des certificats (`notAfter`) sont affichées mais jamais évaluées ;
`whenCreated = clock - n jours` peut être négatif près de `clock = 0` (`adds/objects.ts:577-583`).
